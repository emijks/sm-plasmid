# Пример запуска
```
cd sm-plasmid-clean
python3 plasmid.py -x path_to_xlsx -t path_to_tmp -s path_to_fastq -r path_to_ref -o path_to_results -f 2
```

Код возврата: 0, если все задачи выполнены, иначе 1.

По умолчанию вывод инструментов не печатается, а только пишется в лог-файлы; `-v` (`--verbose-tools`) дублирует его в stdout (см. «Логи»). `-q` (`--quiet-tools`) оставлен для совместимости и соответствует поведению по умолчанию.

Продолжить прогон, завершившийся с ошибками: запустить ту же команду ещё раз.

# Таблица соответствия
Используются колонки `Sample` (полное имя образца, например `20117_SEQ-915-1_DV0-1-2`) и `Map_name` (файл референса в `-r`). Колонки `ID` и `Folder` нужны только при `-f 1`. Строки с пустым `Sample` или `Map_name`, в том числе ячейки с `""` от формул, пропускаются.

# Логи
- В stdout всегда идут таблица запуска, сообщения Snakemake (задачи, ошибки с путём к логу) и `plasmid.py`.
- Вывод инструментов (stdout и stderr команд правила) всегда пишется в лог-файл правила, а с `-v` ещё и дублируется в stdout:
  - `<out-dir>/logs/<OrderID>/<имя образца>/<rule>.log`, например `logs/SEQ-915/20117_SEQ-915-1_DV0-1-2/trim.log`;
  - `<out-dir>/logs/refs/<референс>/<rule>.log` — `dna2fa`, `fa2fa`, `bwa_index`, `faidx`;
  - `<out-dir>/logs/summary_table.log`.
- Лог Snakemake целиком Snakemake сам сохраняет в `.snakemake/log/` в каталоге запуска.

# Каталоги
| Параметр | Назначение |
|----------|------------|
| `-s` | FASTQ; только чтение (монтируется в контейнер как `ro`) |
| `-r` | референсы (`.dna` или `.fa`); только чтение (`ro`) |
| `-o` | результаты по каталогам заказов (см. ниже) и `logs/` |
| `-t` | базовый каталог для промежуточных файлов (можно `/tmp`): внутри используется каталог прогона |

Раскладка `-o`:
```
<out-dir>/
  summary.tsv
  pipeline_status.tsv
  logs/            (см. «Логи»)
  SEQ-746/
    20117_SEQ-746-41_100003225.bam  .bam.bai  .vcf  .consensus.fasta  .assembly.fasta  .report.html
    20117_SEQ-746-42_100003226.*
  SEQ-821/
    20113_SEQ-821-6_100003544.*
```
Имя образца разбирается как `<RunID>_<OrderID>-<item>_<SampleID>` (`RunID` — цифры, `OrderID` — `SEQ-<цифры>`, `item` — номер позиции заказа, `SampleID` — произвольный). Если заказ в имени не распознан, результаты попадают в `<out-dir>/NO_ORDER/`, а при запуске выводится предупреждение.

`-o` и `-t` не могут совпадать или быть вложены друг в друга либо в `-s` и `-r`.

Прогон работает в каталоге `<tmp-dir>/sm-plasmid-<хеш пути -o>/` (с файлом-меткой `.sm-plasmid-run`) и пишет только в него. Прочее содержимое `-t` не затрагивается, а прогоны с разными `-o` могут использовать один `-t`. Имя каталога постоянно для данного `-o`, поэтому повторный запуск той же команды ничего не пересчитывает, а после сбоя продолжает с места остановки. Одновременно с одним `-o` может идти только один прогон (блокировка `.lock` в каталоге прогона). Путь печатается в начале прогона (`Run tmp: …`).

Устройство каталога прогона:
- `refs/` — копии и конвертированные референсы, индексы (`temp`);
- `samples/{sample}/` — промежуточные файлы образца (`temp`): склеенные лейны, обрезанные риды, FastQC, IGV;
- `samples/{sample}/<rule>.work/` — рабочий каталог правила, удаляется при успешном завершении правила;
- `system/` — `$TMPDIR` для задач.

Файлы `temp` удаляет Snakemake, как только они больше не нужны. После успешного прогона каталог прогона удаляется целиком; сам `-t` удаляется, только если пайплайн его создал и он остался пуст. После прогона с ошибками каталог прогона остаётся для разбора; повторный запуск той же команды продолжит прогон. Если каталог с таким именем существует, но в нём нет метки `.sm-plasmid-run`, пайплайн не станет его использовать.

# Имена FASTQ
Файлы ищутся по точному имени образца (`Sample`; при `-f 1` — в подкаталоге `ID/Folder/`):

```
{Sample}[_S<n>][_L<lane>](_|.)R<1|2>[_<NNN>].(fastq|fq).gz
```

Например, `20113_SEQ-821-6_100003544_L03_R1.fq.gz`, `S1_S3_L001_R1_001.fastq.gz`, `S1_L002_R2.fq.gz`, `S1_R1.fastq.gz`, `S1.R2.fq.gz`. Файлы образца `S10` не относятся к образцу `S1`. Несколько лейнов склеиваются; у каждого R1 должен быть парный R2.

# Вывод при запуске
Сначала печатается таблица образцов, которые будут обработаны (`sample`, `order`, `reference`, `files`), затем список пропущенных строк таблицы (нет референса или FASTQ) и предупреждений.

# Референсы
Если в `-r` есть и `X.dna`, и `X.fa`, используется `X.dna` (`ruleorder: dna2fa > fa2fa`), при этом выводится предупреждение.

# Статус-таблица
После выполнения всех стадий `plasmid.py` вызывает функцию `make_status_table()` из `scripts/make_status_table.py` (её можно запустить и отдельно, как скрипт) и создает статус-таблицу следующего формата

|Столбец|Описание|
|-------|--------|
|sample|Идентификатор образца|
|order|Заказ (`SEQ-…`) из имени образца; `-`, если не распознан|
|reference|Статус наличия референсной последовательности|
|fastq|Статус наличия парных FASTQ-файлов|
|assembly|Статус сборки|
|bam|Статус выравнивания|
|bam_index|Статус индексирования BAM|
|variant_calling|Статус вариант-коллинга|
|snp_count|Количество обнаруженных SNP|
|indel_count|Количество обнаруженных инделов|
|consensus|Статус консенсусной последовательности|
|report|Статус итогового HTML-отчёта|

Какие бывают статусы:
- **MISSING** ожидаемый файл отсутствует; для входных данных означает отсутствие референса или FASTQ-файлов
- **EMPTY** файл существует, но имеет нулевой размер
- **INVALID** файл присутствует, но имеет некорректный формат (например, FASTA не содержит последовательностей)
- **OK** этап успешно выполнен, файл существует и имеет корректный формат
- **SKIPPED** этап не выполнялся, поскольку отсутствовали необходимые входные данные (например, референс или FASTQ-файлы)
- **NO_VARIANTS** файл вариантов создан, однако SNP и инделы не обнаружены.
